# Studio UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local web UI (`python -m studio open`) where the owner creates a shorts batch, chooses topics, watches each step run, reviews the videos and exports them, with the two owner approvals as buttons.

**Architecture:** New `studio/` package (FastAPI + plain JS, like Backlot) that holds no batch state of its own. State is derived from `projects/<id>/` files; every change goes through `lib/shorts/*` and `scripts/shorts_batch.py`. Thinking steps run the owner's `claude -p` CLI headlessly, return JSON, and Studio validates and saves it.

**Tech Stack:** Python 3.10+, FastAPI/Starlette (already used by Backlot), plain JavaScript, pytest, ffmpeg (existing), `claude` CLI 2.1.x.

**Spec:** `docs/superpowers/specs/2026-11-05-studio-ui-design.md`

## Global Constraints

- Runs on `127.0.0.1` only, default port `4760`; only `Host` 127.0.0.1 / localhost accepted (HTTP 400 otherwise).
- Every POST/PUT needs header `X-Studio-Token` equal to the random token generated at server start; missing/wrong is HTTP 403.
- Free only: no paid provider, size cap and licence log stay on; exports stay `private`; nothing is ever uploaded.
- Approvals happen only through `POST .../gates/<idea|review_queue>/approve`. No AI code path may call a `--approve` command.
- One job at a time per batch; a second start returns HTTP 409.
- Batch ids match `^[A-Za-z0-9_-]+$` and must be folders in `projects/` whose `project.json` has `pipeline_type == "shorts-factory"`; media paths must resolve inside the batch folder.
- `claude` is run with cwd = `<repo>/projects/.studio-work` (never the repo root: the repo's `CLAUDE.md` would hijack it), `--no-session-persistence`, `--output-format json`, `--json-schema`, an explicit `--tools` allowlist, and the result is read from the JSON field `structured_output`.
- Tests never call real `claude`, download, or render: they use `FakeAi` and a fake command runner.
- Run tests with `./.venv/Scripts/python.exe -m pytest`. The existing suite must stay green.

## Review Focus

- Two tabs click Run or Approve at the same moment: second gets 409 and nothing runs twice. (Task 3, Task 8)
- A batch id or media path like `../x`, `..%2f`, or an absolute path: 404, never a file outside the batch. (Task 1, Task 7)
- A spec edit that fails validation: nothing is saved, violations are returned. (Task 1, Task 7)
- Server restarted while a job was running: the job shows failed and its step is not stuck `running`. (Task 3)
- AI exits non-zero, times out, returns invalid JSON, or returns more/fewer videos than asked: spec unchanged, clear error. `claude` not installed: clear message. (Task 5, Task 6)
- Footage candidate over the size cap: next candidate is tried; if none fit the step fails with the reason. (Task 8)

### Task 2: Step state derivation

**Files:**
- Create: `studio/steps.py`, `tests/studio/test_steps.py`

**Interfaces:**
- Consumes: `batch_dir`, `lib.shorts.spec.load_spec/validate_spec`, `lib.shorts.batch.read_batch/render_fingerprint`
- Produces:
  - `STEPS = ("topics","script","footage","render","review","export")`
  - `step_states(project_dir: Path, running: str | None = None, failed: str | None = None) -> dict[str, str]`; values are `locked|ready|running|done|failed|stale`
  - `gate_status(project_dir: Path, gate: str) -> str` returns `"approved"` when `checkpoint_<gate>.json` has `status == "completed"` and `human_approved is True`, `"awaiting"` when the file exists otherwise, `"none"` when absent

Rules: `topics` done = idea gate approved. `script` done = topics done and `validate_spec(..., "script")` empty. `footage` done = script done and `"visuals"` empty. `render` done = footage done and, for every video, `renders/<id>.mp4` exists and `read_batch(...)` entry `render_hash == render_fingerprint(spec, video)`; if files exist but a hash differs the step is `stale`. `review` done = review_queue gate approved and the checkpoint timestamp is newer than every render file. `export` done = every approved video has `export/<NN>-<id>/video/output.mp4`. A step is `locked` when its predecessor is not `done`. `running`/`failed` apply to the named step; later steps stay `locked`.
